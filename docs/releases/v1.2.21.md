## Highlights

### Heartbeat (`#FW-64` follow-up)

Follow-up on tag **`firmware-v1.2.18`**. That release already appends waterfall and offload counters to the debug-log heartbeat (`rec seg lost evic wrows full ofok offail`). This release **does not replace those keys**. It appends three complementary fields and gives `dbglog_hb` enough stack to format the longer line.

| Key | Source | Why it is not redundant |
|---|---|---|
| `ring=count/capacity` | `spectrogram_get_status()` | RAM spectrogram ring fill. Distinct from LittleFS `wrows`/`full`. |
| `st=` | `wf_offload_get_stat().last_status` | Last HTTP status, or a negative transport error. Distinguishes a latched `offail` counter from a receiver that is healthy again. |
| `stk=` | `uxTaskGetStackHighWaterMark(NULL)` | Remaining stack of `dbglog_hb`, **bytes** on ESP32-S3 (`StackType_t` is `uint8_t`). Not present in `/api/*`. |

`dbglog_hb` is raised **3072 → 4096**. `stk` is sampled **before** `snprintf` / `write_raw`.

### ASWF time contract + axis latch (`#P-024` / issue #49)

While wall-clock `< 2023-11-14` (`WF_SANE_EPOCH`):

- segment header `started_at` is `0` (relative axis per `ASWF_FORMAT.md`)
- per-row `timestamp` is `0`
- RAM segment registry uses the same `started_at`

Segment age (10 min finalize) **and** the half-age `make_room` trigger use `esp_timer`, not `time(NULL)`.

**Latch:** `s_seg_rel_axis` is set in `seg_open_new` from the header decision. `seg_write_row` uses that latch so an SNTP jump mid-segment cannot mix a relative header with absolute row timestamps. `spectrogram_time_synced()` still only rewrites the RAM session anchor (no `seg_finalize` from that callback).

### Waterfall Clear (`#FW-65`)

The Clear button fix (`collect` names → `closedir` → `unlink`, honest `ok` / `err=delete`) was written on **1.2.18** without bumping `version.txt`. Public `main` **1.2.20** does **not** contain it. **1.2.21 is the first numbered release with that fix.** Without it, 1.2.21 and the Clear branch would be siblings; the next increment (1.2.22) hardens races on top of this tree.

`{"ok":true}` only when `seg_*` is gone. `"err":"recording"` if recording. `"err":"delete"` if files remain.
