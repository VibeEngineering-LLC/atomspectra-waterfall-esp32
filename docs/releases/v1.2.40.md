# AtomSpectra Waterfall — прошивка 1.2.40

Установка прошивки с GitHub со страницы «Система» больше не зависит от фрагментации кучи: задача установки создаётся один раз при старте. При нехватке памяти плата отвечает 503 и страница показывает понятное сообщение. Все исправления и доработки 1.2.39 сохранены.

## Исправлено

- **Установка с GitHub не стартовала при фрагментации внутренней RAM (issue #63).** Задача установки создавалась при нажатии кнопки «Установить» со стеком 8192 Б во внутренней RAM; если крупнейшего свободного внутреннего блока не хватало, создание задачи не удавалось, а интерфейс показывал «Ошибка сети». Теперь задача создаётся один раз в `ota_gh_client_init` при старте со статическим стеком и статическим блоком управления во внутренней RAM (`.bss`), живёт постоянно и запускается уведомлением задачи при нажатии кнопки. Приоритет (4), ядро (1) и размер стека (8192 Б) прежние.
- **Различие «занято» и «нет памяти».** Проверка занятости и захват задачи выполняются под одним замком: два одновременных запроса не запустят две установки. Ответ `POST /api/ota/github/install`: 409 `Install already running` — установка уже идёт; 503 `Install task unavailable: out of memory` — задача при старте не создана. Прежде оба случая возвращали 409 с текстом `Install already running or OOM`.
- **Страница «Система» (RU/EN).** При ответе 503 показывается «Недостаточно свободной памяти платы для запуска установки. Перезагрузите плату и повторите.» (`Not enough free board memory to start the install. Reboot the board and try again.`), при 409 — «Установка уже выполняется.»; прочие ошибки по-прежнему показываются как «Ошибка сети».
- **Хост-тест.** `tests/host/ota_install_task_check.sh` (6 проверок исходника: способ создания задачи, уведомление, порядок кодов 503/409) подключён к `make test`; отдельный мутационный скрипт `tests/host/mutate_ota_install_task.sh` (три мутанта плюс исходный код до исправления) запускается вручную. Также обновлены `wiring_check.sh` и `spec_writers.py` под код 1.2.38 и 1.2.39.

## Что не вошло и ограничения

- **Постоянная цена по памяти:** 8 КиБ стека и около 350 Б блока управления и переменных заняты внутренней RAM всегда (статическая внутренняя RAM `.bss` выросла с 113 240 до 121 784 Б по `idf.py size` ветки исправления). Раньше эта память бралась только на время установки.
- **Кнопка «Установить» на плате в этом выпуске не нажималась.** Релиза 1.2.40 на GitHub на момент проверки нет, поэтому сама установка с GitHub (скачивание, проверка образа, запись) этой сборкой не проверена. Проверены сборка, хост-проверка исходника и работа платы с этим образом.
- **Хост-тест проверяет исходник, а не поведение кучи:** `ota_github_client.c` использует `esp_http_client`, `esp_ota` и mbedTLS, заглушек которых в `tests/host/glue` нет.
- **Буфер HTTP-клиента установки (8192 Б, выделяется `esp_http_client`)** в исправление не входит. По сгенерированному `sdkconfig` (`CONFIG_SPIRAM_USE_MALLOC=y`, `CONFIG_SPIRAM_MALLOC_ALWAYSINTERNAL=16384`) он при нехватке внутренней RAM может уходить в PSRAM; на плате это не проверялось.
- Ограничения 1.2.39 сохраняются (единичный провал HTTP до 4,5 с в одном прогоне, значение `sn` в TXT после замены прибора, порт `rest` в TXT задан константой, код журнала команд `AWF_CMDLOG` покрыт хост-тестами частично и др.; см. `v1.2.39.md`).
- **Хвост задержек HTTP в прогоне нагрузки не объяснён.** В живом прогоне (см. ниже) каждые около 60 с на 2–4,7 с задерживались ответы сразу нескольких клиентов (408 ответов дольше 1 с из 17 445, 186 дольше 2 с, максимум 4 719,9 мс; p99 2 023 мс). Те же моменты, с точностью до секунды, повторились в 10-минутных прогонах того же скрипта одновременно на двух платах; последовательный `curl` к одной плате за 6 мин (1 800 запросов) не дал ответов дольше 0,25 с. Причина не установлена. Повторный прогон того же скрипта 35 мин одновременно на двух платах (1.2.40 и 1.2.39) хвоста не показал: p99 178 и 226 мс, максимум 1 083 и 1 501 мс, ответов дольше 2 с нет. Прошивка 1.2.40 регрессом не подтверждена, но источник первого хвоста не найден.

Загрузчик, таблица разделов и `ota_data_initial.bin` побайтно совпадают с набором 1.2.39.
