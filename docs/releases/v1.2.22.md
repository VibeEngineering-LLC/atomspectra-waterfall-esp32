# v1.2.22 — waterfall Clear hardening

**Date:** 2026-08-30  
**Upstream target:** `VibeEngineering-LLC/atomspectra-waterfall-esp32` via fork `Steaeavean/atomspectra-waterfall-esp32`

Private lab identifiers (LAN IP, MAC, board-id, absolute paths) are **not** published here.

This is an increment **on 1.2.21**. Clear (`#FW-65` collect-then-unlink) already landed in 1.2.21. 1.2.22 does not introduce Clear; it hardens races.

---

## Highlights

- After the pin wait, re-read `recording` / `s_seg_fp`. Do not delete if recording resumed.
- `s_wf_epoch++` happens **before** unlink so writers and the uploader abort.
- `s_seg_pinned` is cleared only if it still matches the value captured before the wait.
- Offload `post_segment` checks a lock-free `spectrogram_clear_is_pending()` between HTTP chunks (`HTTP_TIMEOUT_MS` is 20 s; pin-wait alone is not enough). Cancel returns a negative rc; the caller uses `spectrogram_offload_release`, not `_done`.
- LittleFS has no `EBUSY` on unlink of an open file — do not rely on that.
